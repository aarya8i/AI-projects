# Trip Readiness Planner

Enter a destination, dates, activity, group size and experience level. The app checks the daily forecast and returns:

- a **Go / Caution / Reconsider** verdict with a short reason
- the **top 3 weather risks**, each with a mitigation
- a **gear checklist** that starts with the Scout Ten Essentials, followed by activity- and weather-specific additions
- the **place name the forecast was resolved to**, so you can confirm it's the right location

It's a planning aid only, not a substitute for official conditions and your own judgment.

## How it works

```
Browser ──POST /api/plan──▶ api/plan.ts (Vercel serverless function)
                              1. validate input (zod)
                              2. geocode location   → Open-Meteo Geocoding API (first match)
                              3. check dates against today at that location
                              4. daily forecast     → Open-Meteo Forecast API (°F, mph, inches)
                              5. summarize forecast (trip days only)
                              6. ask the model      → Cerebras (qwen-3.8-27b), strict JSON schema
                              7. validate output (zod) → 502 if invalid
                              8. Ten Essentials + model's extra gear, duplicates removed
```

- The browser only ever calls `POST /api/plan`. API keys and third-party calls stay on the server.
- The Scout Ten Essentials are a hardcoded list, never generated by the model.
- `qwen-3.8-27b` is a reasoning model, and its reasoning tokens count toward `max_completion_tokens`. The function sets a 4096-token budget and `reasoning_effort: "low"`, and reads only `message.content`. A cut-off (`finish_reason: "length"`) or empty answer returns a clear 502.

**Stack:** Vite, React, TypeScript, plain CSS, zod, Vitest, the Cerebras TypeScript SDK (`@cerebras/cerebras_cloud_sdk`), and Vercel.

## Project structure

```
api/plan.ts          serverless function (the only backend endpoint)
api/plan.test.ts     handler tests (fetch + Cerebras SDK mocked)
src/lib/             pure, unit-tested logic shared by server and browser
  validateInput.ts     input + date-range validation
  dates.ts             time-zone-safe YYYY-MM-DD helpers
  summarizeForecast.ts Open-Meteo daily data → trip summary
  checklist.ts         Ten Essentials + duplicate-free merging
  validateModelResponse.ts  zod schema for model output + strict JSON schema
  prompt.ts            system and user prompts
  api.ts               browser-side client for /api/plan with friendly errors
src/components/      TripForm, Results, ErrorBanner
src/App.tsx          single page
```

## Setup

Requirements: Node.js 20+ and a free [Cerebras API key](https://cloud.cerebras.ai/).

```bash
git clone <your-repo-url>
cd AI-projects/trip-planner
npm install
```

### Environment variables

| Variable | Required | Default | Notes |
|---|---|---|---|
| `CEREBRAS_API_KEY` | yes | none | Read only inside `api/`. Never put it in a `VITE_` variable, frontend code, or git. |
| `CEREBRAS_MODEL` | no | `qwen-3.8-27b` | Any Cerebras model that supports `json_schema` structured output. |

`.env.example` lists them with empty values. All `.env*` files except `.env.example` are git-ignored.

## Running locally

The API is a Vercel function, so use `vercel dev` (not `npm run dev`, which serves only the frontend):

```bash
npx vercel login                 # once
npx vercel link                  # once: link this folder to a Vercel project
npx vercel env add CEREBRAS_API_KEY development   # paste your key when prompted
npx vercel dev                   # http://localhost:3000
```

> In our testing, `vercel dev` did not pick up `CEREBRAS_API_KEY` from `.env.local`. Adding it as a Vercel **Development** environment variable (above) worked.

Quick API check from a second terminal (use dates within the next 16 days):

```bash
curl -s -X POST http://localhost:3000/api/plan -H 'content-type: application/json' \
  -d '{"location":"Yosemite Valley","startDate":"2026-11-01","endDate":"2026-11-02","activity":"Day hike","groupSize":3,"experience":"Beginner"}'
```

### Tests and checks

```bash
npm test            # Vitest: unit + handler tests, no real network calls
npm run typecheck   # tsc across app, node and api configs
npm run lint        # oxlint
npm run build       # typecheck + production build
```

## Deploying to Vercel

This app lives in a subfolder of the `AI-projects` repo.

1. In Vercel, **Add New → Project** and import the `AI-projects` repository.
2. Set **Root Directory** to `trip-planner`. Vercel detects the Vite framework, and `api/plan.ts` becomes the `/api/plan` function automatically.
3. Under **Settings → Environment Variables**, add `CEREBRAS_API_KEY` (and optionally `CEREBRAS_MODEL`) for Production and Preview. You can also use `npx vercel env add CEREBRAS_API_KEY production`.
4. Deploy. Later pushes to `main` redeploy automatically.

## Known limitations

- **The location uses the first geocoding match.** Ambiguous names can resolve to the wrong place. For example, "Mount Rainier" resolved to *Mount Rainier, Maryland*, not the Washington volcano. The results page shows the resolved place with a hint to try a more specific name (e.g. a nearby town or park), but there's no picker for choosing between matches.
- **Forecasts only cover the next 16 days** (Open-Meteo's limit), so trips must start today or later and end within that window.
- **Weather, not trail conditions.** The forecast is for a grid point and may not reflect summit or ridge conditions, snowpack, closures, fire, or avalanche danger.
- **The model's verdict and risks can vary** between runs and can be wrong. Output is schema-validated, but its judgment isn't. That's why the disclaimer exists.
- **Duplicate detection in the checklist is simple.** It ignores case, punctuation and plurals, but not synonyms ("rain jacket" and "rain gear" both appear).
- **The free Cerebras tier has rate limits.** Heavy use may return "service is having trouble" errors.
- The UI components have no automated tests. The logic they rely on (`src/lib/`) and the API handler do.
