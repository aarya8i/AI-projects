# Trip Readiness Planner: rules for Claude Code

## Project
Portfolio app for a Glencliff Labs internship application. Deadline: Oct 29, 2026, 10:59 PM. Stay within v1 scope.

## v1 spec
- Inputs: location (text), start date, end date, activity (Day hike, Backpacking, Car camping, Trail running), group size (1–20), experience level (Beginner, Intermediate, Advanced).
- Outputs: verdict (Go / Caution / Reconsider) with a 1–2 sentence reason; gear checklist starting with the Scout Ten Essentials, then activity- and weather-specific additions; top 3 weather risks, each with a mitigation; the resolved place name used for the forecast.
- Scout Ten Essentials (hardcoded constant, never generated by the model): pocketknife, first-aid kit, extra clothing, rain gear, water bottle, flashlight, trail food, matches and fire starters, sun protection, map and compass.

## Stack and architecture
- Vite + React + TypeScript, Vitest, plain CSS (no UI libraries). One Vercel serverless function at api/plan.ts. Deployed on Vercel with Root Directory set to trip-planner (this folder is inside my AI-projects repo).
- The browser calls only POST /api/plan. It never calls Open-Meteo or Cerebras directly.
- api/plan.ts: validate input → geocode with Open-Meteo Geocoding API (first result) → fetch daily forecast (Fahrenheit, mph, inches) → summarize → call the model via the official Cerebras SDK (@cerebras/cerebras_cloud_sdk) → validate → return JSON.
- Provider is Cerebras (switched from Anthropic on Oct 28, 2026 for free API access). Model from CEREBRAS_MODEL env var, default "qwen-3.8-27b".
- qwen-3.8-27b is a reasoning model: reasoning tokens count toward max_completion_tokens. Use max_completion_tokens 4096 and reasoning_effort "low". Read only choices[0].message.content, never the reasoning field. finish_reason "length", "content_filter", or empty content returns a 502.
- Structured output: response_format json_schema with strict: true, derived from the zod schema by toStrictJsonSchema(). Cerebras strict mode rejects minItems/maxItems/minLength/maxLength/$schema and needs additionalProperties: false on every object; zod enforces the stripped rules after parsing.
- The model returns JSON only: { verdict, reason, additionalGear: [{item, why}], risks: [{title, detail, mitigation}] } with exactly 3 risks. Validate with zod; invalid output returns a clear 502, never a crash.
- The server merges additionalGear after the Ten Essentials and removes duplicates.
- Logic lives in pure, testable functions (input validation, forecast summarizing, checklist merging, response validation).

## Security
- The Cerebras key lives only in the CEREBRAS_API_KEY environment variable, read only inside api/. Never put it in frontend code or any VITE_ variable, never log it, never commit it.
- Never create a .env file containing a real key. .env.example has empty placeholders only. .gitignore must keep ".env*"; if scaffolding creates its own .gitignore, merge them.

## Validation and errors
- Trip starts today or later, ends within 16 days from today (Open-Meteo limit), end ≥ start, location 2–100 chars. Helpful 400 errors.
- Friendly UI messages for: location not found, dates out of range, API failure.
- Show a disclaimer: planning aid only, not a substitute for official conditions and your own judgment.

## Conventions (agreed decisions)
- Shared pure code lives in `src/lib/`; `api/plan.ts` imports it with explicit `.js` extensions (ESM on Vercel). Files inside `src/lib/` also use `.js` extensions for relative imports, because `tsconfig.api.json` (nodenext) typechecks them too.
- `.gitignore` keeps `.env*` and adds `!.env.example` so the empty-placeholder example file can be committed.
- The API handler is a Web-standard `export async function POST(req: Request): Promise<Response>`.
- Date checks take `today` as a parameter (pure and testable). The server computes `today` in the geocoded location's timezone, not UTC.
- 16-day limit: Open-Meteo's 16 forecast days include today, so `end ≤ today + 15`.
- Typecheck: `npm run typecheck` (`tsc -b` over app, node, and api tsconfigs). Tests: `npm test`.
- Vercel CLI is a devDependency: run locally with `npx vercel dev`.
